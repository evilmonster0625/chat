mallchat-frequency-control

频率控制（限流）模块 — 通用分布式限流基础设施
概览 Overview

为 MallChat 提供通用的接口频率控制能力，防止接口被恶意或意外高频调用导致服务过载。支持三种分布式限流策略，可注解式或编程式调用，贯穿从 AOP 切面到 Redis 存储的完整链路。

核心思想 Core Idea

所有限流策略复用同一个骨架，差异只在于"如何判断超限"和"如何计数"。

1
reachRateLimit

检查是否达到阈值，超限则抛 FrequencyControlException

2
supplier.get

未超限，执行业务逻辑

3
addStatistics

finally 块中计数 +1，无论成败

抽象类中的核心方法：

private <T> T executeWithFrequencyControlMap(
    Map<String, K> frequencyControlMap,
    SupplierThrowWithoutParam<T> supplier
) throws Throwable {
    // ① 先检查是否超限
    if (reachRateLimit(frequencyControlMap)) {
        throw new FrequencyControlException(...);
    }
    try {
        // ② 没超限就执行业务
        return supplier.get();
    } finally {
        // ③ 无论成功失败，计数 +1
        addFrequencyControlStatisticsCount(frequencyControlMap);
    }
}
三种分布式限流策略 Strategies

固定窗口

Redis: String · 类: TotalCountWithInFixTimeFrequencyController

基于 INCR + 过期时间实现。如"10 秒内最多 5 次"，key 过期自动重置计数器。实现简单，但存在窗口边界突发流量问题。

滑动窗口

Redis: ZSet · 类: SlidingWindowFrequencyController

ZSet 记录每次请求时间戳，检查时删除窗口外过期记录，只统计窗口内请求。平滑程度由 windowSize + period 控制。

令牌桶

Redis: String · 类: TokenBucketFrequencyController

TokenBucketManager 维护带补充机制的令牌桶，每次消耗 1 个令牌。支持突发流量（积攒的令牌可短时间内用完）。

限流对象 Target

通过 @FrequencyControl(target = ...) 指定对什么维度进行限流：

EL（SpEL 表达式）

最灵活，通过 Spring 表达式自定义限流 key，如根据 #request.userId、roomId 等。

IP / UID

从 RequestHolder 获取请求 IP 或登录用户 ID，对单个 IP 或用户进行限流。

使用的设计模式 Patterns

模板方法

Template Method

AbstractFrequencyControlService 定义算法骨架，子类实现 reachRateLimit() 和 addStatistics()，复用控制流程。

策略模式

Strategy

三种限流算法各自独立封装，运行时通过工厂按名称获取对应策略实现。

工厂模式

Factory

FrequencyControlStrategyFactory 以 Map<String, AbstractFrequencyControlService> 存储策略实例，@PostConstruct 自动注册。

注解 + AOP

Annotation + Aspect

@FrequencyControl 声明式限流，FrequencyControlAspect 解析注解、构建 DTO 并委托给工厂。

两种使用方式 Usage

注解式（推荐）

// 10 秒内最多 3 次，按用户限流
@FrequencyControl(time = 10, count = 3,
    target = FrequencyControl.Target.UID)
public Void sendMessage(...) { ... }

编程式

FrequencyControlUtil.executeWithFrequencyControl(
    "TotalCountWithInFixTime",
    new FixedWindowDTO("key", 10, SECONDS, 3),
    () -> doSomething()
);
双套实现对比 Implementations

Redis 分布式实现

基于 Redis 原子操作（INCR、ZSet），支持跨进程 / 多实例限流，适合生产环境。

  • 固定窗口 — String INCR
  • 滑动窗口 — ZSet 时间戳集合
  • 令牌桶 — String 令牌数 + 补充器

JVM 本地实现

单机限流，基于 synchronized + 内存数据结构，作为算法示例存在。

  • FixWindow — 计数器 + 时间窗口
  • SlideWindow — LinkedList 时间戳滑动
  • TokenBucketRateLimiter / LeakyBucketRateLimiter
